# FirstIslamicCoin genesis blocks

Pinned in `firstislamiccoin-core/src/kernel/chainparams.cpp`, which `assert()`s
every hash below at startup. Generated by
`firstislamiccoin-core/contrib/genesis/generate_genesis.py`, after its
`--self-test` rebuilt CodexaCoin's and Blackcoin's live genesis blocks exactly.

## Common to every network

| | |
|---|---|
| Timestamp phrase | `FirstIslamicCoin 12/Sep/2026 — Bismillah, the first Shariah-conscious Proof-of-Stake network` |
| Phrase / coinbase `scriptSig` | 94 bytes / **99 of the 100** the consensus rules allow |
| `nTime` | `1789171200` (2026-09-12 00:00:00 UTC) |
| `nVersion` | `7` — `CheckBlockHeader()` rejects less once protocol v2 is active |
| Premine | **14,000,000,000 FIC** in **1,000 outputs of 14,000,000 FIC** |
| Proof of work | scrypt (`GetPoWHash()`); the block hash itself is SHA256d |

The phrase leaves one byte of `scriptSig` headroom: one more character and the
genesis block becomes invalid. Replacing the em dash with an ASCII hyphen would
free two bytes.

### Mainnet is a placeholder until the key ceremony

The mainnet premine pays `<02 50929b74…803ac0> OP_CHECKSIG` — BIP-341's
"nothing up my sleeve" point `H`, whose private key nobody knows. A chain
started from this genesis block could neither spend nor stake its premine, so it
could never produce block 1. `CMainParams` also sets
`m_genesis_premine_placeholder`, which makes the node refuse to start mainnet
and say why.

At the key ceremony (Phase 10): choose the real premine outputs, pick an `nTime`
near launch, re-mine with `generate_genesis.py`, paste the values in, and clear
the placeholder flag. `fic_genesis_tests` will then need its placeholder
expectation flipped — a deliberate speed bump.

Staking only accepts single-key outputs (P2PK, P2PKH, P2WPKH, P2TR), so the
ceremony cannot pay the whole premine straight into a multisig cold wallet: at
least enough of it to produce blocks until the chain is self-sustaining must go
to single keys held by whoever bootstraps the network.

## Why the premine is 1,000 outputs

Getting a chain with no proof of work to produce its first block needs two
consensus changes from CodexaCoin, which minted its premine through 500 blocks
of proof of work instead:

**1. The genesis outputs must exist.** Bitcoin-derived nodes never add the
genesis coinbase to the UTXO set. FIC's `ConnectBlock()` does, and the genesis
transaction is indexed like any other.

**2. They must be usable at once.** A coin normally waits `nCoinbaseMaturity`
blocks (500 on mainnet) before it can stake or be spent. With no proof of work,
nothing could produce those 500 blocks. Genesis outputs are exempt — safely,
because the genesis block can never be reorganised away, and that is the only
risk maturity protects against. The exemption, `IsStakeMature()` in `pos.h`, is
applied in `CheckProofOfStake`, `CheckKernel`, `CacheKernel`,
`Consensus::CheckTxInputs`, the mempool's reorg check, and the wallet's
maturity and staking-selection code. It applies to height-0 coins only.

That alone still stalls the chain at block 2. Staking a genesis output spends it
into a new coinstake output, and that output *is* subject to the full maturity
wait. With one genesis output, block 1 would consume it and leave nothing
eligible to stake block 2. With 1,000, each of the first 500 blocks can stake a
different genesis output; by height 501 the coinstake output from block 1 has
matured, the one from block 2 follows at 502, and the chain keeps itself going.
`feature_fic_genesis_premine.py` runs exactly this on regtest, past the
maturity window.

## Launch note: start the first staker out of "initial block download"

A node stakes only once it has peers and has left initial block download, and
it considers itself in IBD while its tip is more than 24 hours old. At launch the
tip is the genesis block, whose timestamp is fixed. Whoever stakes the first
blocks must run with `-maxtipage` set longer than the genesis block's age, until
recent blocks exist. Regtest is exempt from this gating.
